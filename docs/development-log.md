# 깐보's Ptero 개발 과정 기록

이 문서는 완성된 기능만이 아니라, 요구사항을 정리하고 운영 환경에서 문제를 해결하면서 V3.1까지 변화한 과정을 기록합니다.

## 1. 출발점

Pterodactyl에서 여러 게임 서버를 관리하고 있었고, Discord를 사용하는 접속자들이 현재 어떤 서버가 열려 있는지 쉽게 확인할 수 있으면 좋겠다는 요구에서 시작했습니다.

초기 아이디어는 Discord에서 Pterodactyl을 제어하는 관리 봇이었습니다. Start/Stop/Restart, CPU/RAM, 콘솔 같은 기능도 후보에 있었습니다.

하지만 실제 사용 장면을 정리하면서 목표를 다음처럼 바꿨습니다.

> 관리자가 Discord에서 서버를 조작하는 도구가 아니라, 접속자가 보고 "이 서버가 지금 열려 있구나"를 바로 알 수 있는 현황판.

## 2. 실행 방식

Linux 호스트 직접 실행, Webhook 스크립트, 외부 호스팅과 Pterodactyl 내부 Node.js 서버 방식을 비교한 뒤, 이미 운영 중인 Pterodactyl에서 재시작·로그·파일 관리가 쉽다는 점 때문에 Generic Node.js Egg 안에서 봇을 실행했습니다.

## 3. V1 — 기본 상태 현황판

- Discord 봇 로그인
- Pterodactyl 서버 목록 조회
- 각 서버 `/resources` 상태 조회
- Discord Embed 생성 및 주기적 수정
- 서버 이름, 상태, 게임 종류 표시

기능은 동작했지만 서버가 늘수록 화면이 복잡해졌고 `Unknown` 게임 표시가 자주 나타났습니다.

## 4. 실제 배포 문제

### Docker 안에서 `127.0.0.1` 사용

`ECONNREFUSED 127.0.0.1:80` 오류를 통해 Pterodactyl 컨테이너 내부의 localhost와 Ubuntu 호스트의 localhost가 다르다는 점을 확인했습니다. Panel URL을 SER8의 내부 네트워크 주소로 바꿔 해결했습니다.

### Application API와 Client API

봇의 `/api/client/...` 호출에는 관리자용 Application API가 아니라 일반 계정의 Client API Key(`ptlc_...`)가 필요했습니다. 프로젝트 목적에 맞는 권한 범위를 선택했습니다.

### Discord Missing Permissions

`DiscordAPIError[50013]: Missing Permissions`는 역할 전체보다 상태 메시지를 보낼 특정 채널의 권한 문제였습니다. 채널 보기, 메시지 보내기, 링크 첨부, 메시지 기록 보기 권한을 설정해 해결했습니다.

## 5. V2 — 수동 게임 등록 제거

초기에는 Egg 이름, 서버 이름과 `games.json` 예외 설정으로 게임 종류를 표시했습니다. 신규 서버가 생길 때마다 설정을 수정해야 했기 때문에 자동화 목적과 맞지 않았고, V2에서 게임 종류 표시 자체를 제거했습니다.

## 6. V3 — 접속자용 현황판

실행 중인 서버의 업타임과 서버 열림·종료 알림을 추가했습니다. 봇 재시작 직후 기존 서버 상태가 모두 알림으로 발생하지 않도록 이전 상태가 없는 서버는 알림에서 제외했습니다.

## 7. Smart Update

30초마다 Pterodactyl 상태는 확인하지만 Discord 메시지는 상태가 바뀌거나 업타임 갱신 시간이 되었을 때만 수정하도록 분리했습니다.

```text
상태 확인
├─ 상태 변화 있음 → 즉시 현황판 수정 + 알림
└─ 변화 없음 → Discord 수정 안 함
                 └─ 업타임 갱신 시간이 되면 현황판 수정
```

기본값은 `UPDATE_INTERVAL_SECONDS=30`, `BOARD_REFRESH_SECONDS=300`입니다.

## 8. V3.1 — 디자인 단순화

최종적으로 게임 종류, CPU/RAM/Disk, 서버 IP, 관리자용 버튼, 콘솔 기능 등 사용 목적과 직접 관계없는 요소를 제거했습니다. 서버 이름, 현재 상태, ONLINE 서버 업타임, 열림·종료 알림만 남겼습니다.

## 9. 최종 판단

이 프로젝트에서 가장 큰 변화는 기능 추가가 아니라 기능 제거였습니다. 실제 사용자를 서버 관리자보다 게임에 접속하려는 Discord 멤버로 정의하면서 UI와 코드가 단순해졌고, 신규 서버도 별도 설정 없이 자동 반영되는 구조가 되었습니다.
